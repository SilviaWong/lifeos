# LifeOS 个人综合管理系统 — 产品需求文档（PRD）

**文档版本：** V1.0  
**产品形态：** 用户端（微信小程序/uni-app）+ 管理端 Web + Java 后端  
**目标版本：** MVP → V1.0  
**说明：** 本文档以用户提供的项目介绍材料为功能依据。具体字段、状态、权限、接口和边界规则属于复刻时的工程化设计，需在开发中按实际 UI 再校准。

---

## 1. 产品概述

### 1.1 产品定位
LifeOS 是面向个人用户的综合生活管理系统，将个人健康数据、目标计划、日程待办、番茄钟、习惯打卡、收支、生活记录和提醒集中管理，并通过统计看板呈现个人执行情况。管理端用于用户管理、全局配置、分类/标准维护及运营数据查看。

### 1.2 产品目标
- 让用户在一个入口完成日常记录、计划执行和数据回顾。
- 将目标拆解为可执行任务，并通过进度、打卡和专注记录形成反馈。
- 通过趋势图和统计指标帮助用户了解阶段性变化。
- 为运营/管理员提供必要的用户、分类、标准和系统数据管理能力。

### 1.3 产品边界
V1.0 不包含医疗诊断、银行账户直连、自动记账、复杂社交、多人协作、AI 健康建议、第三方穿戴设备同步。健康数据仅作个人记录和趋势展示，不构成医疗建议。财务模块是手工记账，不代表真实银行余额。

### 1.4 目标用户与角色
| 角色 | 说明 | 主要权限 |
|---|---|---|
| 普通用户 | 使用个人生活管理功能 | 仅访问自己的业务数据 |
| 管理员 | 管理平台用户及全局配置 | 查看用户列表、维护健康标准/收支分类、查看平台统计 |
| 超级管理员 | 系统维护角色 | 管理员账号与系统级配置（可作为后续能力） |

### 1.5 核心指标
- 用户活跃：DAU/MAU、近 7/30 日登录用户数。
- 功能使用：各模块新增记录数、活跃用户数、模块使用排行。
- 个人执行：目标完成率、待办完成率、习惯打卡率、专注时长。
- 个人生活：健康记录趋势、收入/支出/结余统计。

## 2. 信息架构与导航

### 2.1 用户端
建议底部主导航控制在 5 个入口：
1. 首页：今日摘要、快捷入口、待办/习惯/目标概览。
2. 健康：健康记录、趋势、健康标准提示。
3. 目标：目标列表、目标详情、子任务与进度。
4. 日程：待办列表、日历视图、番茄钟。
5. 我的：习惯、收支、物品、借还、备忘录、日记、个人设置。

### 2.2 管理端
- 数据看板
- 用户管理
- 健康管理（健康记录查询、健康标准配置）
- 财务管理（收支分类）
- 运营管理（模块使用统计、提醒规则/消息）
- 系统管理（管理员与角色；可在 MVP 后实现）

## 3. 功能需求

优先级定义：P0 = MVP 必须；P1 = V1.0 重要；P2 = 后续增强。

### 3.1 用户认证与个人资料（P0）
**功能**
- 用户注册、登录、退出登录。
- JWT 认证；登录后获取个人资料。
- 修改昵称、头像、密码。
- 管理端账号登录与角色校验。

**规则**
- 用户名/手机号/邮箱（按实际登录方式选定）需唯一；首版可先采用用户名或手机号登录。
- 密码使用 BCrypt 等安全算法哈希存储，禁止明文保存。
- JWT 仅承载身份与必要声明；业务接口从服务端认证上下文取得 userId，不信任客户端传入的 userId。
- 禁用用户不可登录；退出登录由客户端清理令牌，若需服务端即时失效再增加 token 黑名单机制。

**验收**
- 未登录请求受保护接口返回 401。
- 普通用户不能通过修改请求参数读取其他用户数据。
- 管理接口必须经过管理员角色授权。

### 3.2 首页与 ECharts 数据看板（P0/P1）
**用户首页**
- 展示今日待办数、已完成数、习惯打卡数、当前目标进度、今日专注时长。
- 展示健康/收支快捷摘要（可配置是否显示）。
- 提供各模块快捷入口。

**管理端看板**
- 用户总数、活跃用户数、模块使用排行。
- 按日期范围查看新增用户、活跃用户和模块使用趋势。
- 健康记录数量、财务记录数量等运营统计。

**规则**
- 所有统计必须支持日期范围；默认近 7 天或近 30 天。
- 明确统计口径：活跃用户以有效登录或关键业务行为为准；模块使用以成功业务操作为准，不能仅统计页面打开。
- 大数据量场景可增加按日汇总表；首版直接聚合明细表即可。

### 3.3 健康记录与趋势（P0）
**记录类型**
- 步数（steps）
- 睡眠时长（sleep_hours）
- 体重（weight）
- 饮水量（water_ml）
- 饮食/备注（meal 或 note；可记录文字及可选热量）

**功能**
- 新增、编辑、删除个人健康记录。
- 按日期、类型查询。
- 按周/月查看趋势图。
- 展示健康标准范围；超出范围时给出非诊断性提示。

**规则**
- 一条记录代表某个用户在某个时间点的一项指标；同一天允许多条记录。
- 数值必须校验单位和合理范围，具体上下限由产品配置决定。
- 健康标准按指标编码、适用范围、生效时间维护；不应硬编码在前端。
- 删除采用逻辑删除或物理删除，首版统一逻辑删除。

### 3.4 目标与子任务（P0）
**功能**
- 创建、编辑、归档、删除目标。
- 设置标题、描述、开始日期、截止日期、优先级。
- 目标下创建多个子任务，支持完成/取消完成。
- 目标详情显示子任务完成进度。

**规则**
- 目标状态：NOT_STARTED、IN_PROGRESS、COMPLETED、ARCHIVED。
- 子任务状态：TODO、DONE。
- 有子任务时进度 = 已完成子任务数 / 有效子任务总数 × 100%，保留整数或一位小数。
- 无子任务时进度由用户手动设置或保持 0；首版建议不允许手动完成进度，展示“尚未拆解”。
- 子任务完成状态变化后重新计算目标进度；目标完成状态由用户显式确认或在全部子任务完成时提示确认。
- 目标和子任务均按 user_id 隔离。

### 3.5 日程待办（P0）
**功能**
- 创建、编辑、删除待办。
- 设置标题、描述、计划开始时间、截止时间、优先级、提醒时间。
- 支持待办列表、日期筛选、状态筛选。
- 完成/重新打开待办。

**规则**
- 状态：TODO、IN_PROGRESS、DONE、CANCELLED。
- 截止时间不得早于开始时间。
- 完成时记录 completed_at。
- 待办可关联目标（可选）；目标删除时待办关联置空，不级联删除待办。
- 提醒功能首版仅保存提醒配置；消息推送渠道可后续接入。

### 3.6 番茄钟（P0）
**功能**
- 配置专注时长、短休息、长休息、长休息间隔。
- 开始、暂停、继续、结束一轮专注。
- 保存专注记录，可选关联待办或目标。
- 展示今日/周专注时长。

**规则**
- 前端计时器负责实时倒计时，后端保存会话开始、结束、实际专注秒数和结束原因。
- 状态：RUNNING、PAUSED、COMPLETED、ABORTED。
- 后端以服务端时间校验开始/结束时间差，不能完全相信客户端上报时长。
- 一个用户允许存在的 RUNNING 会话数量首版限制为 1；通过事务/唯一业务校验保证。
- 暂停/恢复明细首版可不记录；若要精准统计净专注时长，再增加 session_segment 表。

### 3.7 习惯打卡（P0）
**功能**
- 创建、编辑、暂停、归档习惯。
- 设置习惯名称、描述、频率、目标次数和开始日期。
- 每日打卡、取消当日打卡。
- 展示连续打卡天数、累计打卡数和月历。

**规则**
- 首版频率支持 DAILY、WEEKLY；复杂自定义周期后续扩展。
- 每个习惯每天最多一条有效打卡，唯一约束 (habit_id, checkin_date)。
- 连续天数按习惯频率计算；每日习惯按连续自然日，周习惯按连续周计算。
- 补卡能力暂不纳入 MVP，若开放需记录补卡标识与操作审计。

### 3.8 收支管理与统计（P0）
**功能**
- 新增、编辑、删除收入/支出记录。
- 分类选择、金额、日期、备注。
- 按月/年/分类统计收入、支出、结余。
- 管理端维护全局收支分类。

**规则**
- 类型：INCOME、EXPENSE。
- 金额使用 DECIMAL(12,2)，必须大于 0；币种首版默认 CNY，保留 currency_code。
- 结余 = 收入合计 - 支出合计；不把结余解释为银行账户余额。
- 用户可使用系统分类；自定义分类可作为后续增强。
- 删除记录后统计结果应同步变化。

### 3.9 生活记录：物品、借还、备忘录、日记（P1）
**物品管理**
- 记录物品名称、分类、数量、存放位置、购入日期、备注。
- 支持搜索、编辑、归档。
- 借出/归还形成借还记录，记录借用人、借出日期、预计归还日期、实际归还日期和状态。

**备忘录**
- 标题、正文、标签、置顶、归档。
- 支持关键字搜索。

**日记**
- 日期、标题、正文、心情（可选）、天气（可选）。
- 默认仅本人可见；管理端不提供普通日记正文浏览能力。

### 3.10 跨模块提醒（P1）
**场景**
- 待办截止提醒。
- 习惯打卡提醒。
- 目标截止提醒。
- 自定义提醒。

**规则**
- 提醒规则可启用/停用，配置触发类型、提前量、重复规则。
- 提醒消息记录生成、已读、发送状态。
- 定时任务需幂等：同一用户、同一规则、同一业务日期/触发时间不能重复生成。
- 首版站内消息即可，不承诺短信/微信模板消息送达。

### 3.11 模块使用记录（P1）
- 记录关键业务操作：新增健康记录、完成待办、打卡、记账、完成番茄钟等。
- 字段包括用户、模块编码、动作编码、业务对象 ID、发生时间。
- 不记录敏感正文；避免将日记正文、密码等写入日志。
- 管理端据此统计模块活跃度和排行。

## 4. 核心业务流程

### 4.1 登录流程
1. 用户提交账号和密码。
2. 服务端校验账号状态和密码哈希。
3. 生成 JWT，返回 token 与用户基础资料。
4. 客户端保存 token；后续请求携带 Authorization: Bearer。
5. 服务端解析 token 并建立认证上下文，业务层从上下文取得 userId。

### 4.2 目标执行流程
1. 用户创建目标并设置起止日期。
2. 用户将目标拆分为多个子任务。
3. 用户完成子任务，系统更新任务状态。
4. 服务端计算目标进度并返回。
5. 所有子任务完成时提示用户确认目标完成。

### 4.3 番茄钟流程
1. 用户选择专注时长，可关联待办/目标。
2. 客户端请求创建会话，服务端创建 RUNNING 记录。
3. 客户端本地倒计时；暂停/恢复仅由客户端控制时需同步状态，首版可只支持开始/完成/中止。
4. 完成或中止时提交结束请求。
5. 服务端校验会话归属和时间，保存最终状态与实际时长。

### 4.4 习惯打卡流程
1. 用户进入习惯列表。
2. 用户对当天习惯打卡。
3. 服务端校验习惯归属、状态、日期和唯一性。
4. 创建打卡记录，返回累计次数和连续天数。
5. 取消打卡时软删除记录并重新计算统计。

## 5. 数据与权限规则

- 所有用户业务表必须包含 user_id。
- 普通用户只能访问自己的数据；所有查询、更新、删除都必须同时校验业务主键和当前 user_id。
- 不允许仅依赖前端隐藏按钮实现权限控制。
- 管理员只访问管理端明确授权的数据；日记正文默认不开放给管理员。
- 时间统一存储为 DATETIME，应用层统一使用约定时区；建议数据库连接与服务端统一 UTC 存储，展示时转换为用户时区。若首版仅面向单一时区，也必须在项目中固定并写明。
- 金额使用 DECIMAL，不使用 FLOAT/DOUBLE。
- 所有重要表包含 created_at、updated_at；软删除字段 deleted。
- 外键可在开发初期由业务层维护；下方 SQL 使用索引和逻辑关联，不大量设置物理外键，避免软删除与跨模块生命周期耦合。

## 6. API 规划

统一前缀 `/api`，统一响应建议：
```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "..."
}
```
分页请求：`pageNum`、`pageSize`；分页响应包含 `records`、`total`、`pageNum`、`pageSize`。

## 7. 非功能需求

### 7.1 安全
- 密码 BCrypt 哈希；JWT 密钥通过环境变量管理。
- HTTPS 部署；生产环境关闭 SQL 详细日志。
- 参数校验、SQL 注入防护、XSS 输出处理。
- 用户数据按 user_id 做服务端隔离。
- 管理接口 RBAC；关键管理操作记录审计日志。
- 日记、健康和财务属于个人敏感内容，最小化采集、最小化展示。

### 7.2 性能
- 常规列表接口目标 P95 < 500ms（开发/测试环境基准，非绝对承诺）。
- 分页查询必须限制 pageSize（建议最大 100）。
- 统计查询按用户、日期和类型建立索引。
- 看板避免一次返回大量明细，优先返回聚合结果。

### 7.3 可维护性
- 模块化单体，按业务域拆分包。
- Controller 负责协议层，Service 负责业务规则，Mapper 负责持久化。
- 统一异常、响应、参数校验、日志 traceId。
- 数据库变更纳入版本化迁移脚本（Flyway/Liquibase 二选一）。

### 7.4 可观测性与备份
- 记录应用错误日志和关键操作日志，不记录密码/token/日记正文。
- MySQL 定期备份并验证恢复流程。
- 提供健康检查接口；部署后检查应用、数据库连接状态。

## 8. 版本规划

### MVP（建议先交付）
1. 登录注册、个人资料。
2. 首页摘要。
3. 健康记录 CRUD + 趋势。
4. 目标/子任务。
5. 待办 CRUD。
6. 番茄钟基础记录。
7. 习惯打卡。
8. 收支记录与月度统计。
9. 管理端登录、用户列表、健康标准/收支分类维护。

### V1.0
- 物品与借还、备忘录、日记。
- 提醒规则与站内提醒。

## 9. 验收标准（核心）

| 模块 | 验收点 |
|---|---|
| 认证 | 注册/登录成功；错误密码拒绝；受保护接口校验 JWT |
| 数据隔离 | A 用户无法读取、修改或删除 B 用户数据 |
| 健康 | 可新增多类型记录；按日期筛选；趋势统计正确 |
| 目标 | 子任务增删改、完成后进度计算正确 |
| 待办 | 状态流转正确；完成时间记录正确 |
| 番茄钟 | 开始、完成、中止状态正确；异常时长被拒绝 |
| 习惯 | 同一习惯同一天不能重复打卡；取消后统计正确 |
| 收支 | 金额精度正确；按月分类统计与明细一致 |
| 物品借还 | 未归还记录可查；归还后状态与日期正确 |
| 提醒 | 同一规则同一触发窗口不重复生成消息 |
| 管理端 | 无权限角色不能访问管理接口；全局分类配置生效 |
| 看板 | 统计口径与明细数据核对一致 |

## 10. 开发约定与待确认项

**默认技术约定**
- Java 17 + Spring Boot 3.x + MyBatis-Plus + MySQL 8。
- 用户端 uni-app + Vue 3 + Pinia；管理端 Vue 3 + Vite + Element Plus + ECharts。
- JWT + BCrypt；首版不依赖 Redis。
- 统一逻辑删除字段 `deleted`；业务数据以 user_id 隔离。

**开工前需确认**
1. 登录账号采用手机号、用户名还是微信授权；建议先用户名/手机号 + 密码。
2. 健康指标最终范围及单位。
3. 习惯频率是否只支持每日/每周。
4. 是否允许自定义收支分类；当前 SQL 预留系统/用户分类。
5. 日记是否支持图片附件；当前首版仅保存文本和封面 URL。
6. 提醒首版是否只做站内消息。
7. 是否需要管理员查看个人明细；建议默认不开放日记正文及非必要个人隐私字段。

**实施原则：先打通一个完整纵向链路（登录 → 待办 → 统计），再横向扩展模块。**
